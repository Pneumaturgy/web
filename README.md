# Pneumaturgy — production site

Plain static HTML/CSS/JS (no build step). This is the production
implementation of `design-handoff/project/Pneumaturgy v2.dc.html`, the final
Claude Design prototype described in `design-handoff/chats/chat1.md`. See
`PLAN.md` for the implementation plan and the decisions behind the stack
choice.

## Structure

```
index.html      one-page site: nav, hero, work grid, studio, manifesto,
                 join/footer, plus 11 project "sheets" rendered as a modal
css/style.css    all styling — design tokens, layout, the sheet/modal system
js/main.js       opens/closes project sheets, Escape/backdrop-click to
                 close, syncs the open sheet to the URL hash (e.g.
                 /#geomancy is shareable and deep-links straight to it)
<key>/          one share link per project (e.g. vapor/, geomancy/),
                 generated by scripts/share_pages.py; see "Share links"
scripts/         share_pages.py, which writes those share links
assets/          images referenced by index.html (logos, figure glyphs,
                 Geomancy gem photography, screenshots)
design-handoff/  the original Claude Design export this site was built
                 from — chat transcript, Notion export, source prototype —
                 kept for provenance, not needed to run the site
docs/            the studio's written record, taken from Notion in full —
                 manifesto, every design doc, the Godot handbook. The site
                 is a curated read of this; these docs are the source
```

## Docs

`docs/` holds the complete prose the site is drawn from — see
[docs/README.md](docs/README.md) for the index, and
[docs/site-coverage.md](docs/site-coverage.md) for what the site leaves out.
Nothing in `docs/` is served by the site; it is read on GitHub.

## Preview locally

No install, no build. Any static file server works, e.g.:

```
python3 -m http.server 8000
# open http://localhost:8000
```

## Deploy

Static hosting only — point any of these at the repo root:

- **GitHub Pages** — Settings → Pages → deploy from this branch, root.
- **Cloudflare Pages / Netlify / Vercel** — set the project (or build)
  output directory to `/` (repo root), no build command needed.

## Extending

Each project write-up lives in its own `<article class="sheet-doc"
data-doc="...">` block inside `index.html`. `js/main.js` matches sheets to
their opening card purely by the shared `data-sheet` / `data-doc` value, so
adding a new project is:

1. Add a card button with a new `data-sheet="key"`.
2. Add a matching `<article data-doc="key">` in the sheet overlay.
3. Run `python3 scripts/share_pages.py` to make its share link, and commit
   the new `key/` folder.

## Share links

Send people `https://pneumaturgy.github.io/web/<key>/`, not `/#<key>`.
Discord, iMessage, Slack and the rest ignore everything after `#` and never
run JavaScript, so a `#` link previews as the whole site. Each `<key>/`
folder is a tiny page with that project's own preview tags (title,
description, image) that then redirects to `/#<key>`.

Every project sheet has a **Share** button next to Close. It shows that
project's share link with a Copy button, links for WhatsApp, X, Bluesky,
Reddit, Facebook and email, and on phones the system share sheet. It
works out the link from the sheet's key, so new projects get it for free.

`scripts/share_pages.py` (standard library only) writes all of them from
`index.html`: the sheet's `<h1>` is the title, its lede is the description,
and its first image (else the card's, else the flame) is the picture.
Re-run it whenever a project's title, lede or image changes. To say
something different in the preview than on the sheet, put
`data-share-title`, `data-share-description` or `data-share-image` on the
`<article>`; Vapor Music does this to say "open beta" and "free download".

Discord caches previews for a while, so a changed preview can take time to
show on a link that was already posted.
